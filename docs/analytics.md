# Аналитика

Аналитика в `bookshop_py` доступна **только пользователю с ролью `admin`** и открывается через ссылку «📊 Аналитика» в навбаре. Страница использует Bearer-токен авторизованного пользователя (не API-токен).

## Что показывает дашборд

**KPI-карточки** (живые цифры из БД): всего заказов, выручка, уникальные клиенты, средний чек, количество городов, количество отзывов, открытых жалоб.

**Вкладки:**

| Вкладка | Источник (эндпоинт) | Что показывает |
|---------|---------------------|----------------|
| Заказы | `/api/analytics/order-facts` | Список заказов: покупатель, дата, сумма, статус |
| Товары / Продажи | `/api/analytics/product-sales` | Продажи по товарам: цена, количество, сумма, категория |
| Выручка | `/api/analytics/daily-revenue` | Выручка/заказы/средний чек по дням |
| События | `/api/analytics/event-log` | Журнал событий (воронка) |
| Города | `/api/analytics/cities` | Топ городов: заказы, клиенты, выручка |
| Отзывы | `/api/analytics/reviews` | Оценки пользователей с названием книги |
| Жалобы | `/api/complaints` | Заявки о проблемах + смена статуса |

## Сводные показатели (KPI)

Эндпоинт `/api/analytics/kpi` возвращает словарь:
- `orders_total` — число заказов (кроме `cancelled`)
- `customers_total` — уникальных пользователей в заказах
- `revenue_total` — сумма `orders.total_amount` (кроме `cancelled`)
- `avg_order` — средний чек
- `reviews_total` — число отзывов
- `complaints_open` — жалобы со статусом `new` / `processing`
- `cities_total` — количество уникальных городов из `orders.city`

## Метрики и выводы (по реальным данным)

Помимо живого дашборда, в проекте есть **оффлайн-анализ** на pandas (`analysis/analyze.py` и `.ipynb`), который считает продуктовые метрики по заказам и даёт рекомендации.

**Фактические цифры за ~6 месяцев на демо-данных:**

| Метрика | Значение |
|---|---|
| **GMV** (заказы кроме отменённых) | **269 180 ₽** |
| Заказов (не отменённых) | 172 |
| Покупателей | 52 |
| **AOV** (средний чек) | **1 565 ₽** (медиана 1 280 ₽, σ 1 053 ₽) |
| **ARPPU / LTV** (на покупателя) | **5 177 ₽** (медиана 4 890 ₽) |
| Среднее заказов на покупателя | 3.31 (медиана 3) |
| Повторных покупателей (≥2 заказа) | **78.8%** (41 из 52) |
| Отменённых заказов | 13 (7%) |

**Что показывают данные (выводы):**
- **Выручка сконцентрирована** в нескольких городах (Ростов, Нижний, Челябинск, Новосибирск) малым числом покупателей — риск.
- **Когорты:** майская (35 новичков) возвращается на ~40%, а **новые июль–сентябрь почти не повторяют** → отток новых клиентов.
- **Август — провал** в заказах/выручке (19 заказов, ~34 тыс. ₽) на фоне июльского пика (63.9 тыс. ₽).
- **Операционно:** 56 заказов «ждут обработки» (`new`/`processing`), 13 отменённых — нет автоматического продвижения статусов.

**Идеи A/B-тестов** (гипотезы, не проведённый эксперимент):
1. Промокод/email после первой покупки для новых когорт → метрика: повторные покупки в m1.
2. Акция/подборка к августу → метрика: GMV августа.
3. Точечные акции в топ-городах (Ростов, Нижний) → метрика: AOV города.
4. Автоматизация статусов/напоминание об оплате → метрика: доля `completed` за 3 дня.
5. Дополнить воронку (логировать `view_cart`, `checkout`) → метрика: cart-abandonment.

> **Важно про воронку.** Классическую воронку `view → cart → order` по событиям `event_log` построить **нельзя**: в журнале есть `product_view`, `add_to_cart`, `order_created`, но нет `view_cart`/`checkout`, а `add_to_cart` (89) **меньше** `order_created` (185). Данные-сиды неполные. Сейчас воронка оценивается **по статусам заказов** (какая часть доходит до `completed`), а полноценная cart-abandonment — после добавления логирования шагов.

**Наглядные графики**: `analysis/out/chart_monthly_revenue.png` (выручка/заказы по полным месяцам), `chart_geo_revenue.png` (топ городов), `chart_repeat.png` (повторные покупки).

## Гео (города)

В `orders` есть поле `city`. Оно заполняется: при создании заказа из `OrderCreateIn.city`, а также обновляется из профиля пользователя при авторизованном заказе. На аналитике города группируются по `orders.city` (исключая пустые и отменённые).

## Отзывы (reviews)

Таблица `reviews` хранит `product_id`, `user_id`, `rating`, `text`, `created_at`. На аналитике соединяется с `users` (имя) и `products` (название книги) — отображается **название книги** и **имя пользователя**.

## Данные для DS / выгрузки

Витрины `v_order_facts`, `v_product_sales`, `v_daily_revenue`, `v_event_log` (в БД `bookshop_full`) доступны через защищённые эндпоинты. Из Python:
```python
import pandas as pd, pymysql
conn = pymysql.connect(host='localhost', user='root', password='',
                       db='bookshop_full', charset='utf8mb4')
order_facts = pd.read_sql("SELECT * FROM v_order_facts", conn)
daily = pd.read_sql("SELECT * FROM v_daily_revenue", conn)
conn.close()
```

Для этого нужны `pandas` и `pymysql`.

## Готовый пайплайн аналитики (два шага)

Аналитика разделена на **выгрузку** и **анализ**, потому что в окружениях не всегда есть одновременно PyMySQL и pandas.

```bash
# 1) выгрузка из БД в CSV (venv проекта, PyMySQL) — не требует pandas
.venv\Scripts\python.exe analysis\report.py

# 2) метрики + графики по CSV (окружение с pandas)
conda run -n analytics python analysis\analyze.py      # или открой analysis/analyze.ipynb
```

### Шаг 1 — `analysis/report.py` (выгрузка)

Подключается к БД через `DATABASE_URL` (из `.env`), выгружает всё в `analysis/out/` и печатает KPI-сводку. Создаёт файлы:
- `order_facts.csv` — факты заказов
- `product_sales.csv` — продажи по товарам
- `daily_revenue.csv` — выручка по дням
- `event_log.csv` — журнал событий
- `reviews.csv` — отзывы
- `complaints.csv` — жалобы
- `orders.csv` — заказы (включая `city` и `status`)

### Шаг 2 — `analysis/analyze.py` / `analyze.ipynb` (метрики + графики)

Читает CSV из `analysis/out/` и считает продуктовые метрики: **GMV, AOV (среднее/медиана/σ), ARPPU/LTV, повторные покупки, когорты по месяцу первой покупки, гео (топ городов), отмены и статусы**. Пишет дополнительные CSV (`monthly.csv`, `geo.csv`, `repeat_purchases.csv`, `cohorts.csv`, `monthly_full.csv`) и строит PNG-графики.

> **Файлы пишутся в UTF-8 с BOM (`utf-8-sig`)** — открываются корректно в Excel. Папка `analysis/out/` в `.gitignore` (не храним результаты в git).

> **Май и ноябрь** — неполные месяцы (границы выборки): они **исключены из помесячной динамики и графика**, но **остаются в итоговых суммах (GMV, средний чек)** и в **когортах** как реальные продажи.

## Демо-данные

БД `bookshop_full` наполнена реалистичными данными примерно за **полгода**: 52 клиента из ~22 городов, ~185 заказов (completed/shipped/processing/new/cancelled), отзывы, повторные покупки, журнал событий, жалобы. Это позволяет сразу строить метрики «как в реальном проекте» (см. `docs/database.md`).
