## Каталог / поиск

### UC-01: Просмотр каталога
- **Актор:** Покупатель
- **Предусловие:** Покупатель открыл сайт.
- **Основной поток:**
  1. Система загружает категории (`/api/categories`).
  2. Система загружает товары (`/api/products`, по умолчанию все, `limit=500` на фронте).
  3. Покупатель выбирает категорию или вводит поисковый запрос — каталог перезагружается (`?category=` / `?q=`).
  4. Система отображает карточки: название, автор, категория, цена, остаток, сердечко избранного.
- **Результат:** Покупатель видит релевантный список книг.

### UC-02: ИИ-поиск (смарт-матчинг)
- **Актор:** Покупатель
- **Предусловие:** Открыт ИИ-помощник (Bookie, `/#ai-chat`).
- **Основной поток:**
  1. Покупатель вводит фразу своими словами.
  2. Система нормализует фразу, раскрывает синонимы тем, взвешивает по idf.
  3. Система возвращает до `limit` книг с `score`.
  4. Система отображает найденные книги в чате.
- **Альтернатива:** нет результатов → система предлагает переформулировать запрос.
- **Результат:** Покупатель получает релевантные книги по смыслу.

## Корзина / заказ

### UC-03: Добавление в корзину
- **Актор:** Покупатель
- **Предусловие:** Товар в наличии.
- **Основной поток:**
  1. Покупатель нажимает «🛒 В корзину» на карточке.
  2. Система увеличивает количество (`cart[id]`), обновляет счётчик, показывает тост.
- **Результат:** Товар в корзине, счётчик обновлён.

### UC-04: Управление корзиной
- **Актор:** Покупатель
- **Предусловие:** Корзина не пуста.
- **Основной поток:**
  1. Покупатель меняет количество (`setQty`) или удаляет позицию (`removeItem`).
  2. Система пересчитывает сумму и счётчик, перерисовывает корзину.
- **Результат:** Корзина приведена к нужному виду.

### UC-05: Оформление заказа
- **Актор:** Покупатель
- **Предусловие:** Корзина не пуста.
- **Основной поток:**
  1. Покупатель вводит ФИО, email, телефон, адрес (и опционально город).
  2. Система валидирует данные (Pydantic).
  3. Система в транзакции: определяет пользователя (авторизованный или гость по email), создаёт заказ, вставляет состав, списывает остатки, фиксирует статус `new`, пишет историю и событие `order_created`.
  4. Система возвращает `{ order_id, total_amount, status }`.
  5. Система очищает корзину, показывает подтверждение.
- **Альтернативы:**
  - Ошибка валидации → показать ошибку.
  - Ошибка транзакции → `400`, откат.
  - Товар не найден → `404`.
- **Результат:** Заказ создан, корзина пуста.

## Избранное

### UC-06: Добавить/убрать из избранного
- **Актор:** Покупатель (авторизованный)
- **Предусловие:** Покупатель вошёл.
- **Основной поток:**
  1. Покупатель нажимает сердечко на карточке.
  2. Система вызывает `POST /favorites` (или `DELETE /favorites/{id}`).
  3. Система обновляет список избранного, счётчик и сердечки без полной перерисовки каталога.
- **Альтернатива:** не вошёл → просьба войти (`openAuth`), тост «Войдите, чтобы добавлять в избранное».
- **Результат:** Книга добавлена/убрана, счётчик обновлён.

### UC-07: Просмотр избранного
- **Актор:** Покупатель (авторизованный)
- **Предусловие:** Покупатель вошёл.
- **Основной поток:**
  1. Покупатель открывает «❤️ Избранное» в навбаре.
  2. Система загружает `/api/favorites` и рендерит карточки (цена, наличие, название).
- **Альтернатива:** не вошёл → «Войдите, чтобы видеть избранное».
- **Результат:** Список избранного отображён.

## Жалобы

### UC-08: Подать жалобу о проблеме с книгой
- **Актор:** Покупатель (гость или авторизованный)
- **Предусловие:** Существует карточка товара.
- **Основной поток:**
  1. Покупатель нажимает «⚠» на карточке.
  2. Открывается модалка; при авторизации поля префиллятся данными пользователя.
  3. Покупатель указывает тип проблемы, описание и контакты.
  4. Система создаёт жалобу (`POST /complaints`), пишет событие `complaint_created`.
  5. Система показывает подтверждение с номером заявки.
- **Альтернатива:** товар не найден → `404`.
- **Результат:** Жалоба зарегистрирована.

### UC-09: Обработка жалоб (админ)
- **Актор:** Администратор (`admin`)
- **Предусловие:** Пользователь с ролью `admin` вошёл.
- **Основной поток:**
  1. Администратор открывает вкладку «Жалобы».
  2. Система загружает `GET /api/complaints`.
  3. Администратор меняет статус (`PATCH /api/complaints/{id}`).
  4. Система валидирует статус (`new/processing/resolved/rejected`), обновляет и возвращает жалобу.
- **Альтернатива:** роль не `admin` → `403`.
- **Результат:** Статус жалобы обновлён.

## Авторизация

### UC-10: Вход / регистрация
- **Актор:** Покупатель / Администратор
- **Предусловие:** Пользователь не вошёл.
- **Основной поток:**
  1. Покупатель открывает модалку «Войти», переключается на нужную вкладку.
  2. Вводит email/пароль (`/api/auth/login`) или регистрируется (`/api/auth/register`).
  3. Система проверяет пароль (PBKDF2), создаёт подписанный токен, возвращает профиль.
  4. Система сохраняет токен, показывает имя, загружает избранное, обновляет gate аналитики.
- **Альтернатива:** неверные данные → `401`; занятый email → `409`.
- **Результат:** Пользователь вошёл, токен сохранён.

### UC-11: Текущий пользователь / выход
- **Актор:** Покупатель / Администратор
- **Основной поток:**
  1. При загрузке страницы `checkAuth` вызывает `/api/auth/me`.
  2. При успехе обновляет `currentUser`; при ошибке сбрасывает токен и избранное.
  3. Кнопка «⎋» выполняет `logout`: удаляет токен и избранное.
- **Результат:** Состояние авторизации корректно.

## Аналитика

### UC-12: Просмотр KPI и вкладок (админ)
- **Актор:** Администратор (`admin`)
- **Предусловие:** Пользователь с ролью `admin` вошёл.
- **Основной поток:**
  1. Администратор открывает «📊 Аналитика».
  2. `refreshAnalyticsGate` проверяет `currentUser.role === 'admin'`.
  3. Если админ — система загружает `/api/analytics/kpi` и вкладки, строит карточки и таблицы.
  4. Иначе — показывает «Доступ только для администратора».
- **Альтернатива:** роль не `admin` → gate, без загрузки данных.
- **Результат:** Дашборд с KPI и вкладками отображён.

### UC-13: Аналитика города / отзывы / события
- **Актор:** Аналитик / Администратор
- **Предусловие:** Роль `admin`.
- **Основной поток:**
  1. Открывает вкладку «Города» — `GET /api/analytics/cities` (заказы, клиенты, выручка).
  2. Открывает вкладку «Отзывы» — `GET /api/analytics/reviews` (имя, книга, оценка).
  3. Открывает вкладку «События» — `GET /api/analytics/event-log`.
- **Результат:** Таблицы аналитики отображены.

## Здоровье

### UC-14: Проверка состояния API/БД
- **Актор:** Разработчик / DevOps
- **Основной поток:** `GET /api/health` проверяет подключение к БД.
- **Результат:** `{ success: true, data: { status: "ok", db: true } }` или `503`.
