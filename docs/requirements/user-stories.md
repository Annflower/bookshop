# User Stories — bookshop_py

Формат: **Как** `<роль>`, **я хочу** `<действие>`, **чтобы** `<ценность>`.
Приоритеты: **P0** — критично для MVP, **P1** — важно, **P2** — желательно.

> Документ отражает **фактическое** поведение Python-проекта (`bookshop_py`) — вход по ролям, избранное, жалобы, ИИ-поиск, аналитика.

---

## Покупатель (Customer)

### US-01 (P0) — Просмотр каталога
**Как** покупатель, **я хочу** видеть список книг с ценой, автором и категорией, **чтобы** выбрать, что купить.
**Критерии:** каталог показывает название, автора, категорию, цену, остаток; фильтр по категории (`?category=`).

### US-02 (P0) — Поиск книги
**Как** покупатель, **я хочу** искать по названию/автору/описанию, **чтобы** быстро найти конкретную книгу.
**Критерии:** `?q=` ищет по `name`, `author`, `description`.

### US-03 (P1) — ИИ-поиск по смыслу
**Как** покупатель, **я хочу** сформулировать запрос своими словами («про космос», «детская сказка»), **чтобы** найти книгу по теме, даже не зная точного названия.
**Критерии:** `/api/ai/search` нормализует фразу, раскрывает синонимы, возвращает книги с `score`.

### US-04 (P0) — Просмотр карточки товара
**Как** покупатель, **я хочу** видеть подробности книги (описание, наличие, цена), **чтобы** принять решение о покупке.
**Критерии:** если `in_stock=0` — кнопка покупки недоступна.

### US-05 (P0) — Добавление в корзину
**Как** покупатель, **я хочу** добавить книгу в корзину, **чтобы** купить несколько экземпляров.
**Критерии:** счётчик корзины обновляется; количество ограничено наличием.

### US-06 (P0) — Управление корзиной
**Как** покупатель, **я хочу** менять количество, удалять позиции, **чтобы** скорректировать заказ.
**Критерии:** сумма и счётчик пересчитываются (`setQty`, `removeItem`).

### US-07 (P0) — Оформление заказа
**Как** покупатель, **я хочу** ввести данные для доставки (включая город) и подтвердить заказ, **чтобы** оформить покупку.
**Критерии:** валидируются email и обязательные поля; заказ создаётся, корзина очищается; возвращается `order_id`.

### US-08 (P1) — Видеть итоговую стоимость
**Как** покупатель, **я хочу** видеть состав и сумму заказа до подтверждения, **чтобы** избежать сюрпризов.
**Критерии:** чекаут показывает позиции, количество и итог.

### US-09 (P1) — Войти в аккаунт
**Как** покупатель, **я хочу** авторизоваться/зарегистрироваться, **чтобы** привязать заказ к себе и использовать избранное.
**Критерии:** вход/регистрация возвращают токен и профиль; `/me` отдаёт текущего пользователя.

### US-10 (P1) — Избранное
**Как** покупатель, **я хочу** сохранять книги в избранное, **чтобы** вернуться к ним позже.
**Критерии:** добавление/удаление/список по `/api/favorites`; без входа — просьба войти.

### US-11 (P1) — Отзывы о книгах
**Как** покупатель, **я хочу** оставлять отзывы/оценки, **чтобы** помочь другим и видеть рейтинг книги.
**Критерии:** отзывы сохраняются в `reviews`; на аналитике видны имя пользователя и название книги.

### US-12 (P1) — Сообщить о проблеме с книгой
**Как** покупатель, **я хочу** подать жалобу о браке/повреждении, **чтобы** магазин разобрался.
**Критерии:** `POST /complaints` (гость или авторизованный), жалоба попадает админу.

## Владелец / Администратор (Admin)

### US-20 (P0) — Войти в аналитику
**Как** владелец, **я хочу** войти под аккаунтом с ролью `admin`, **чтобы** видеть дашборд.
**Критерии:** обычный вход; при роли `admin` открывается «📊 Аналитика», иначе «Доступ только для администратора».

### US-21 (P0) — KPI-карточки
**Как** владелец, **я хочу** видеть сводные показатели, **чтобы** сразу оценить состояние магазина.
**Критерии:** заказы, выручка, клиенты, средний чек, города, отзывы, открытые жалобы.

### US-22 (P0) — Заказы и продажи
**Как** владелец, **я хочу** видеть факты заказов и продажи по товарам, **чтобы** отслеживать выполнение и бестселлеры.
**Критерии:** вкладки `order-facts` и `product-sales`.

### US-23 (P0) — Выручка по дням
**Как** владелец, **я хочу** видеть динамику выручки/заказов/среднего чека по дням, **чтобы** оценить рост.
**Критерии:** вкладка `daily-revenue`, без отменённых заказов.

### US-24 (P1) — Гео продаж
**Как** владелец, **я хочу** видеть продажи по городам, **чтобы** понять географию спроса.
**Критерии:** вкладка `cities`: заказы, клиенты, выручка по `orders.city`.

### US-25 (P1) — Отзывы
**Как** владелец, **я хочу** видеть отзывы с именем пользователя и книгой, **чтобы** оценить качество контента.
**Критерии:** вкладка `reviews`.

### US-26 (P1) — События (воронка)
**Как** владелец, **я хочу** видеть журнал событий, **чтобы** строить воронку `view → add_to_cart → order_created`.
**Критерии:** вкладка `event-log`.

### US-27 (P1) — Обработка жалоб
**Как** владелец, **я хочу** видеть жалобы и менять их статус, **чтобы** реагировать на проблемы с книгами.
**Критерии:** `GET /api/complaints`, `PATCH /api/complaints/{id}` (статусы `new/processing/resolved/rejected`).

## Аналитик (Analyst)

### US-30 (P0) — Данные для анализа
**Как** аналитик, **я хочу** выгружать факты заказов, продажи, выручку, события, **чтобы** строить отчёты и модели.
**Критерии:** защищённые эндпоинты `/api/analytics/*` + витрины `v_*` в БД.

### US-31 (P1) — Выгрузка через pandas
**Как** аналитик, **я хочу** читать витрины через `pandas.read_sql`, **чтобы** строить метрики в привычном стеке.
**Критерии:** БД доступна по `DATABASE_URL`, витрины готовы.

---

## Разработчик / DevOps (Dev)

### US-40 (P1) — Воспроизводимое окружение
**Как** разработчик, **я хочу** venv + `requirements.txt` + Docker, **чтобы** развернуть проект на чистой машине.
**Критерии:** `.env.example`, Dockerfile, docker-compose; `DATABASE_URL` и `JWT_SECRET`.

### US-41 (P1) — Понимаемый API
**Как** разработчик, **я хочу** Swagger UI и документацию, **чтобы** быстро подключиться к API.
**Критерии:** `/docs` работает; docs/ покрывает API, роли, схему, BPMN.
