# API — bookshop_py

REST API поверх существующей БД `bookshop_full`. Базовый URL — `http://localhost:8000`, все пути с префиксом `/api`. Ответы — JSON. Интерактивная схема доступна по адресу `http://localhost:8000/docs` (Swagger UI FastAPI).

## Аутентификация

Используется **подписанный токен** (не API-токен, не JWT-библиотека). Вход/регистрация возвращают `{ token, user }`.

```
Authorization: Bearer <token>
```

Токен — самоподписанный (`base64url(user_id.expiry).sig`) с TTL **7 дней**. Роль пользователя (`user` / `admin`) хранится в таблице `users.role`. Аналитика и управление жалобами доступны **только пользователю с ролью `admin`**.

## Товары

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| GET | `/api/products` | нет | Список товаров. Параметры: `category` (int, по умолчанию 0 — все), `q` (строка поиска по названию/автору/описанию), `limit` (по умолчанию 50, макс 200), `offset` (по умолчанию 0) |
| GET | `/api/products/{id}` | нет | Карточка одного товара. 404, если не найден |
| GET | `/api/categories` | нет | Список категорий |

## Заказ

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| POST | `/api/orders` | опционально | Создать заказ. Если передан Bearer-токен — заказ привязывается к аккаунту и профиль обновляется; иначе создаётся/находится пользователь по email (гостевой заказ). Тело: `{ name, email, phone, address, city?, items: [{ product_id, quantity }] }`. Ответ: `{ order_id, total_amount, status }`. Ошибки: 400 — товар/остаток, 404 — товар не найден |

> ⚠️ Поле `city` — опционально, сохраняется в `orders.city` и используется в аналитике «Города».

## ИИ-поиск (смарт-поиск по фразе)

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| POST | `/api/ai/search` | нет | Умный поиск: нормализует фразу, раскрывает синонимы тем, взвешивает по idf и ранжирует. Тело: `{ query, limit? }` (limit 1–20, по умолчанию 6). Ответ: `{ success, query, results: [{ ...product, score }] }` |

## Избранное (wishlist)

Требует авторизации (`current_user`).

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/favorites` | Список избранных книг (полные объекты товаров + `fav_added`). Аналог `favorites`-таблицы |
| POST | `/api/favorites` | Добавить книгу. Тело: `{ product_id }`. 404 — книга не найдена. Идемпотентно (без дубликатов). Ответ: `{ in_favorites: true }` |
| DELETE | `/api/favorites/{product_id}` | Удалить из избранного. Ответ: `{ in_favorites: false }` |
| GET | `/api/favorites/{product_id}` | Проверить, в избранном ли книга. Ответ: `{ in_favorites: bool }` |

## Жалобы / брак / проблемы с книгой

Создание — публичное (гость или авторизованный). Список и смена статуса — **только для админа**.

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| POST | `/api/complaints` | опционально | Создать заявку о проблеме. Тело: `{ product_id, name, email, phone?, issue_type?, description }` (issue_type по умолчанию `damage`). 404 — книга не найдена. Ответ — созданная жалоба + `product_name` |
| GET | `/api/complaints` | **admin** | Список жалоб. Параметры: `status`, `limit` (макс 1000), `offset` |
| PATCH | `/api/complaints/{id}` | **admin** | Сменить статус. Тело: `{ status }` (валидные: `new`, `processing`, `resolved`, `rejected`). 404 — не найдена/неверный статус. Ответ — обновлённая жалоба + `product_name` |

## Авторизация

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| POST | `/api/auth/register` | нет | Регистрация. Тело: `{ name, email, password (≥6), phone?, address?, city? }`. 409 — email занят. Ответ: `{ token, user }` |
| POST | `/api/auth/login` | нет | Вход. Тело: `{ email, password }`. 401 — неверные данные. Ответ: `{ token, user }` |
| GET | `/api/auth/me` | да | Текущий пользователь по токену |

## Аналитика — только для admin

Каждый эндпоинт требует роль `admin`, иначе `403 «Доступ только для администратора»`.

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/analytics/order-facts` | Факты заказов (витрина `v_order_facts`) |
| GET | `/api/analytics/product-sales` | Продажи по товарам (`v_product_sales`) |
| GET | `/api/analytics/daily-revenue` | Выручка по дням (`v_daily_revenue`) |
| GET | `/api/analytics/event-log` | Журнал событий (`v_event_log`). Параметры: `event_type`, `limit`, `offset` |
| GET | `/api/analytics/kpi` | Сводные KPI: заказы, выручка, клиенты, средний чек, отзывы, открытые жалобы, города |
| GET | `/api/analytics/cities` | Топ городов: число заказов/клиентов/выручка |
| GET | `/api/analytics/reviews` | Отзывы с именем пользователя и названием книги. Параметры: `limit`, `offset` |

Формат ответа: обычно `{ success, data }`; только `/api/analytics/reviews` возвращает голый массив (по `response_model`).

## Здоровье

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/health` | Проверка подключения к БД. `{ success: true, data: { status: "ok", db: true } }` или 503 с `success: false` |

## Точные коды статуса

- `200` — успех, `201` — создано (`/api/orders`, `/api/complaints`, `/api/auth/register`)
- `400` — ошибка создания заказа / невалидные данные
- `401` — нет/невалидный токен (нужно войти)
- `403` — роль не `admin` (аналитика / админ-жалобы)
- `404` — объект не найден (товар, книга, жалоба, заказ)
- `409` — email уже занят (регистрация)
